# 热门板块开发计划

创建日期：2026-10-13。状态：本机功能已实现并验收；线上发布、跨交易日持续观察待完成。

本计划依据原 V1.2 基线制定，当前需求已更新为 V1.3。本文持续维护开发范围、步骤和执行状态；本机源实测、代码与自动化已完成，线上证据和跨交易日观察单独记录。当前产品基线见《第一版需求文档》，来源细则见《数据同步说明》，交付证据见《验收记录》。

## 1. 目标与第一版范围

帮助用户完成“发现资金关注的板块 → 观察关注是否持续 → 查看板块内个股”的浏览路径。

新增主导航“热门板块”，入口 `/hot-sectors`。默认采用免费数据，允许延迟；页面优先表达来源口径、实际日期和可用程度。

| 第一版包含 | 后续再做 |
| --- | --- |
| 东方财富行业、概念两类板块 | 按现有 SW2021 一级、二级行业重新聚合资金 |
| 今日、5日、10日资金排行 | 交易所资金筛选、任意时间区间排行 |
| 主力净流入、净占比、同周期涨跌幅排序 | 综合热度评分、排名变动、连续流入天数 |
| 全量板块搜索、分页、资金流入与流出快捷排序 | 板块关注与提醒 |
| 板块近期每日资金趋势、当日订单规模拆分 | 更长历史回填、板块轮动分析 |
| 同源成分股资金排行、进入已有股票详情、返回恢复 | 从热门板块顺序跨股浏览 |
| 本地缓存、独立更新任务、失败保留旧数据、状态提示 | Tushare 可选通道 |

行业与概念、三个排行周期、板块历史和成分股资金均为第一版验收范围。数据验证若发现关键能力不可用，先登记缺口并明确调整范围，不将缺失功能默认为已交付。

## 3. 第一版产品规则

### 3.1 排行与默认状态

- 默认“概念 / 今日 / 主力净流入降序 / 第 1 页 / 每页 20 条”。可切换行业；每页支持 20、50、100 条。
- 排行覆盖资金源提供的全部有效板块，不以市场页精选概念为候选范围。
- 板块搜索在当前板块类型和周期内检索全部缓存结果；第一版支持名称和代码，不额外承诺拼音搜索。
- “资金流入排行”按净流入降序，“资金流出排行”按净流入升序，两者均只显示符合正值或负值条件的板块。无对应符号的数据时明确显示无净流入或无净流出板块。
- 默认排行可包含负值和零值，负值不能称为净流入板块。搜索、类型、周期、方向或排序改变后回第一页。
- 服务端先对完整结果集排序再分页；空值末尾，同值按来源板块代码稳定排序。排名以当前筛选后的顺序显示，源排名另存且不混用。
- 选中板块、类型、周期、搜索、排序、方向、页码保存在 URL；刷新和从个股返回时恢复。
- 概览中的最大净流入、最大净流出、有效板块数量按当前类型和周期的完整批次计算，不随搜索或分页变化；显示“全部行业”或“全部概念”。无正值、无负值时对应项显示“暂无”。

### 3.2 指标与统计口径

| 字段 | 产品规则 |
| --- | --- |
| 主力净流入金额 | 默认排名指标；采用已验证的源字段定义，不自行用成交额或涨跌幅估算 |
| 主力净流入占比 | 沿用来源定义及对应统计周期，不对每日占比简单平均 |
| 同周期涨跌幅 | 今日对应今日，5日、10日对应同周期；缺失显示“—”，不使用今日涨幅替代 |
| 主力净流入最大股 | 使用同源、同周期字段；源仅提供当日值时只在今日视图展示 |
| 订单规模拆分 | 当日超大单、大单、中单、小单净流入，标签明确“当日”；主力与分项关系须通过真实样本确认 |
| 每日资金趋势 | 使用已验证交易日期的每日净额；未完成的当日数据单独标记，不混入已确认盘后日历史 |
| 金额与空值 | 后端统一为元，前端按万/亿展示；占比与涨跌幅以百分数展示；零值、负值、缺失分别处理 |

5日、10日沿用来源的交易日窗口，记录已验证的起止日期和是否包含当日。缺少足够历史时不自行合成完整区间。区间涨跌幅不能相加每日涨跌幅。

资金流向为数据商按其成交分类规则形成的统计指标。页面说明来源和口径，不将其描述为真实机构账户进出或投资评级。

### 3.3 分类、成分与股票入口

- 使用“来源 + 板块类型 + 来源板块代码”作为板块身份；名称只用于展示和搜索。接口包装层若未返回代码，M0 必须验证同源代码获取路径及一一对应关系。
- 排行、资金趋势、资金拆分、成分股资金采用同一来源的板块身份；不按名称将东方财富数据绑定到 SW2021 或通达信成员。
- 成分股浏览复用现有股票池过滤；通过代码与交易所匹配内部股票 ID，使用已验证的证券代码别名，不靠证券简称猜测。
- 板块资金总额保留源完整口径，成分股表只展示本站可浏览股票。页面固定说明“板块资金按来源完整口径统计，股票列表按本站规则过滤”。两者不要求金额相等。
- 未匹配股票、被过滤股票及资金缺失分别计数；原始源行用于核验，不因界面过滤而丢弃。
- “主力净流入最大股”如被过滤或无法匹配，显示不可进入的说明，不自动找下一只替代。
- 成分股资金列表使用资金数据同周期的涨跌字段。引用现有最新行情时单独标注行情日期与时间，不冒充同一资金批次。
- 第一版没有交易所筛选，不把原始板块总额伪装为交易所子集统计。
- 概念会重复包含股票，不汇总全部概念资金为全市场总额；不绘制暗示已知板块间实际资金转移的桑基图。

### 3.4 页面与交互

- 桌面：筛选与概览在顶部，下方板块排行和选中板块详情；详情包含资金趋势、当日拆分、成分股资金表。
- 窄屏：先展示排行，选中板块后进入 `/hot-sectors/:id` 查看完整详情；桌面也支持此详情深链接。
- 表格建议列：排名、板块名称、同周期涨跌幅、主力净流入、主力净占比、同周期主力净流入最大股（源支持时）。成分数量仅在同源名单可用时展示。
- 概览和排行使用同一已发布批次。不同数据区块可能有不同批次，各自显示来源日期和状态，不统一盖章为“已更新”。
- 首次加载显示占位；后续自动更新保留表格、滚动、选中板块、焦点和图表区间。仅替换发生变化的数据。
- 类型、周期、板块快速切换时取消旧请求或忽略迟到结果；不同板块的数据不得短暂互相冒充。
- 进入股票详情通过明确的来源参数携带本站热门板块路径；返回链接显示“返回热门板块”。来源只允许站内约定路径，不能任意跳转。
- 从热门板块进入个股不调用市场列表顺序接口；第一版隐藏或禁用前后股票按钮，市场来源的原有导航保持正常。

| 阶段 | 工作包 | 交付物 | 进入下一阶段的条件 |
| --- | --- | --- | --- |
| M0 数据验证与契约 | 验证来源接口、代码、单位、日期、周期、成分、历史和服务器网络 | 数据能力矩阵、字段映射、脱敏样本、缺口清单、接口契约 | 第一版关键数据链路实取成功，关键语义明确 |

### M0：先验证数据，再冻结实现

候选免费接口如下，能力与参数以锁定版本和真实返回为准：

| 数据 | 候选接口 | 必须核对 |
| --- | --- | --- |
| 行业、概念排行 | `stock_sector_fund_flow_rank` | 两类型 × 三周期，共六组；字段、单位、板块代码、返回条数、分页、日期与周期截止点 |
| 行业每日资金历史 | `stock_sector_fund_flow_hist` | 可用长度、交易日期、空值、重复日期、当日是否完成 |
| 概念每日资金历史 | `stock_concept_fund_flow_hist` | 同上；不能用行业历史替代概念历史 |
| 板块内个股资金 | `stock_sector_fund_flow_summary` 或验证后的同源查询 | 行业和概念是否均支持、今日/5日/10日能力、成员完整性、股票代码与市场 |
| 东方财富板块身份及成分 | 同源目录、成分接口或资金返回 | 排行到详情的代码一致性；不依赖现有概念接口的同名优先逻辑 |

具体任务：

1. 在本机与实际部署服务器分别验证网络；使用现有运行配置，不输出代理凭证、Token 或环境秘密。
2. 逐项获取六组排行，至少抽样 3 个行业和 3 个概念；样本包含正值、负值、缺失或新板块（源存在时）。
3. 核对金额单位、百分数字段、主力定义、分项关系及舍入容差；记录源字段到统一字段的映射。
4. 核对板块代码及目录映射；确认历史和个股资金可查询到同一板块。包装层缺字段时先验证同源补充路径。
5. 核对交易日期、5日/10日窗口、盘中更新时间与收盘确认方式。来源没有精确时间时保存空值；仅显示获取时间并说明其含义。
6. 完成至少一个交易日的盘中多时点、收盘后及下一次启动取数，观察限流、返回条数和日期切换；单次成功不视为长期稳定性承诺。
7. 用现有样本资金与本地股票池验证代码匹配、ST 过滤和无法匹配的处理。
8. 冻结完整性检查规则：来源 total、分页完成条件、已验证目录范围、字段空值策略和异常条数变化门槛。不能直接套用现有行情的 95% 覆盖门槛。

通过门槛：六组排行及抽样板块的历史、成分资金能实取；代码、单位和日期语义可明确表达；部署服务器通过读数验证。暂时无法验证部署环境时，本机开发可继续，但发布门槛保持未通过。

来源日期无法可靠确认时，只能表达“统计日期待确认”，不能标为今日已更新，也不能发布为已确认盘后历史。关键日期长期无法验证、源持续不可用或成分资金关键能力缺失时，登记阻塞项；可继续契约/夹具工作，真实数据交付需先解决来源或明确调整范围。Tushare 不自动启用，不新增付费依赖。

### M1：建立数据模型和批次发布

下列逻辑实体已实现，迁移版本为 0010。实际使用四张表：`FundBoard`/`fund_boards` 保存来源身份；`FundCache`/`fund_caches` 按范围原子保存排行、成分及历史快照，资金行和同源成员置于各自 JSON payload；`FundDaily`/`fund_daily` 保存已过交易日；`FundRun`/`fund_runs` 保存任务状态。无需永久保存每轮盘中数据，不单独新增每轮行明细和成员中间表。下表是逻辑职责，实体名不全部对应独立物理表：

| 实体 | 关键内容 |
| --- | --- |
| `FundBoard` | 内部 ID、来源、类型、源代码、名称；来源/类型/代码唯一 |
| `FundFlowBatch` | 数据集类型、周期、统计日期与区间、源时间、获取时间、版本、覆盖统计、质量状态 |
| `BoardFundFlow` | 批次、板块、净额/占比、对应周期涨跌幅、分项资金、源最大资金股 |
| `BoardFundFlowDaily` | 板块、已确认交易日、每日资金字段、来源和修订信息；同源板块交易日唯一 |
| `FundBoardMember` | 同源板块成员及名单批次/获取时间；源代码与本地股票关联分开保存 |
| `StockFundFlow` | 成分股资金批次、板块、源证券代码/市场、可空本地 ID、周期及资金字段 |
| `FundFlowRun` | 任务范围、开始/完成时间、失败原因、重试时间及最近成功批次 |

- 排行、历史、成分股分别发布；排行按“来源 + 板块类型 + 周期”形成独立批次，不混合不同日期的新旧行。
- 数据先在暂存区解析、校验，再在短事务内写入并切换有效批次；网络获取不占用 SQLite 写事务。
- 失败只更新任务状态，不替换最近有效批次。同日修订允许重新发布，重复导入不得产生重复业务记录。
- 当日盘中资金保存在当前批次，不因电脑时间经过 15:00 就自动写成最终日历史；盘后确认机制由 M0 冻结。
- 增加批次保留策略，避免每几分钟存储全量数据导致无限增长；第一版无需永久保存逐次盘中快照，保留当前有效批次和必要核验信息，日历史独立保留。
- 迁移前使用 SQLite backup 生成一致性备份并检查完整性；复用现有数据库，不另建一套业务库。迁移不覆盖既有行情、行业和概念成员。

### M2：采集、调度与查询接口

- 新增独立资金 provider/job，复用当前有界子进程隔离、超时和错误处理方式；必要时扩展 `ak_worker.py` 白名单。
- 拟新增 `doctor-fund-flow`、`sync-fund-flow`，支持按类型、周期或板块限定范围；命令在实现后写入正式运行说明，目前尚不存在。
- 排行批量获取；历史和成分资金按需后台获取、缓存与去重，同一范围同时只允许一个任务。GET 不等待第三方长请求，不让客户端驱动无限全市场抓取。
- 资金任务使用独立互斥与退避，不占用已有全市场同步锁完成长网络操作；数据库提交保持短事务。重复服务进程不得重复采集同一范围。
- 盘中初始采集间隔建议 5 分钟，三个周期分别有状态，窗口端点对齐；根据 M0 的限流结果调整到 3～5 分钟或更慢。按北京时间及已验证交易日历决定交易窗口，不按周一至周五推断。
- 非交易时段避免持续全量抓取；收盘后执行一次确认抓取，失败有限重试；服务启动按状态补取陈旧范围，不承诺关机或休眠时执行。
- 浏览器可见时每 30 秒读本地缓存，切回页面立即读取；上游更新时间与页面轮询时间独立。
- 第三方失败使用有限重试和退避，错误脱敏；外部源失败不阻断已有行情任务、市场 API 和网站启动。

拟定 API（在 M0 冻结后实现）：

| 接口 | 职责 |
| --- | --- |
| `GET /api/hot-sectors` | 类型、周期、名称/代码、方向、排序、分页；返回完整批次概览及排行 |
| `GET /api/hot-sectors/{id}` | 板块身份、所选周期摘要、当日拆分、各数据区块状态 |
| `GET /api/hot-sectors/{id}/history` | 近期每日资金序列、实际起止日期、缺口、完整性 |
| `GET /api/hot-sectors/{id}/stocks` | 同源成分股资金排行、过滤/匹配/缺失统计、分页 |

公共返回元数据至少包含：`source`、`classification_source`、`period`、`trade_date`、`window_start`、`window_end`、`source_as_of`、`fetched_at`、`batch_id`、`stale`、`pending`、`quality_status`、有效与缺失数量。未知日期或时间为 null，不用获取时间填补。概览与排行绑定同一 `batch_id`。

状态约定：正常、旧数据更新中、旧数据更新失败、无缓存加载中、无数据、数据不完整分别表达。有可用缓存时返回缓存和状态；初次没有缓存且任务处理中时返回结构化 pending，前端有界轮询；不存在的板块为 404。自动按需任务失败后进入退避，页面不能每轮轮询都重新触发外部请求。

### M3：页面、图表与浏览连续性

拟新增 `HotSectorsView.vue`、`HotSectorView.vue`、热门板块工作区、排行表、资金趋势图、拆分图、成分股表和 `useHotSectors.ts`；结合实际复用机会拆分，不为每个静态文本新增组件。

## 6. 风险、依赖与处理

| 风险或依赖 | 处理与交付边界 |
| --- | --- |
| 免费源不可达、限流、字段变化 | 有界请求、退避、样本验证、旧批次保留；长时间不可用先解决来源，不生成假数据 |
| 包装接口缺板块代码或来源日期 | M0 验证同源补充路径；无法证明的字段保持未知，不按名称或电脑日期猜测 |
| 当前通达信概念与东方财富同名不同成员 | 热门板块使用独立同源身份和成分，不改写市场页成员 |
| 全量排行被分页或目录变化截断 | 校验 total/分页/目录及异常规模变化；源确实缺失的数值显示缺失，不补零 |
| 5日/10日端点或日期切换不一致 | 周期和批次分别记录，显式显示区间与状态，不跨日拼接 |
| 图表或个股列表晚于排行更新 | 分区标明批次与日期，不暗示金额可以完整对账 |
| SQLite 写入与既有同步竞争 | 网络取数与数据库提交分离，任务独立互斥、提交短事务 |
| 返回热门板块丢失条件或错误沿用市场导航 | URL 保存来源与状态，专门回归市场/热门两类来源 |
| 额外服务成本或 Token 权限 | 第一版免费；可选付费源需另行明确需求与权限，不自动切换 |
