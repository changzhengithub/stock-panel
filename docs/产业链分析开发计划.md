# 产业链分析开发计划

创建日期：2026-10-13。版本：V1.4。更新：2026-10-14。状态：全部 31 个一级与 134 个二级行业已发布专属经营分析；公司资料核验与分析覆盖分别验收。

本计划依据本次确认的产品设计，结合当前工作区的需求、模型、接口、页面和导航实现制定。计划编制时的产品基线为《第一版需求文档》V1.3，首版实现后已更新为 V1.4。后续 AI、情景推演、事件跟踪仍属于规划范围，不纳入本次交付。

本文持续维护任务、依赖、验收和当前状态，不追加重复的历史审查章节。本次实现基于原有未提交工作继续增量开发；未提交或推送。迁移前已一致性备份，既有股票、行业、行情历史、概念与资金记录数核对保持。

## 1. 产品目标与交付范围

帮助用户完成“输入行业 → 明确分析范围 → 看懂产业链 → 理解影响传导 → 查找节点公司与龙头 → 比较、查看个股和收藏”的完整路径。

产业链可以包含必要的全球供给与应用环节，股票浏览重点覆盖沪深北 A 股。境外或非上市主体可以作为解释产业结构的背景信息，不进入 A 股股票表，也不伪装为本站可浏览证券。

### 1.1 首版与后续范围

| 能力 | 首版 V1 | 后续阶段 |
| --- | --- | --- |
| 行业输入 | 搜索名称、别名；宽泛词返回候选范围；支持已发布产业链 | 未覆盖行业的 AI 待核验草稿 |
| 行业速读 | 行业定义、核心产品、需求来源、关键节点、关注变量 | 基于新增证据辅助更新摘要 |
| 产业链图谱 | 主链、分支、循环关系；简明与完整视图；点击节点与连线 | 跨产业链共享环节探索 |
| 影响分析 | 已审核的条件性分析；经营影响与市场表现分别展示 | 用户选择情景后展示可能的传导路径 |
| 节点公司 | 实际业务、参与方式、经营阶段、报告期、收入及占比、证据 | 更广行业覆盖与证据辅助提取 |
| 节点龙头 | 规模、份额、技术维度的可核验标签；不足时仅列代表企业 | 有同口径数据后扩展比较维度 |
| 股票浏览 | 当前节点/全链、过滤、排序、分页、去重、进入个股与返回 | 产业链股票顺序的上一只/下一只 |
| 公司比较 | 同节点选择 2～4 家公司，比较已取得的同口径字段 | 更长经营历史和多期趋势 |
| 收藏 | 浏览器本地收藏产业链与节点；股票沿用现有自选 | 云端同步不在当前计划内 |
| 数据维护 | 定时采集、变更检测、重建校验、原子发布、失败保留、历史固定、复核清单 | AI 辅助语义提取与事实核验 |

当前提供三条资料专题和 SW2021 的 31 个一级概览、134 个二级业务框架。全行业基线包含真实业务快照、匹配财务与条件分析，不等于全量研究核验。名称/别名/拼音搜索可到达所有已发布范围；近似名称、父子或同一级分类建议附理由，不把建议默认为用户选择。后续 AI 草稿保持独立状态。

### 1.2 样板范围

建议首批建设动力电池、光伏、半导体三条产业链，具体分析边界在 M0 根据资料可用性冻结。半导体需要明确覆盖的是全链概览还是某个细分方向，避免以少数公司代表整个行业。

每条样板覆盖其范围内的核心供给、制造、应用和必要辅助环节；节点数量按行业事实确定。首版股票名单属于“已确认收录名单”，不声称穷尽所有相关公司。资料不足的节点保留并注明缺口，不为达到数量目标编造公司或龙头。

## 3. 首版产品规则

### 3.1 输入与范围确认

- 主导航新增“产业链分析”，入口 `/industry-chains`；分析页 `/industry-chains/:id`。
- 搜索覆盖全部已发布产业链的名称、别名和已登记细分范围；支持中文、规范代码和拼音，复用已有拼音处理能力。
- 输入“新能源”等宽泛词时列出候选分析范围。单一明确匹配可以直接进入；多个候选必须选择，不由系统自行选择一个行业。
- 产业链 ID 独立于行业代码和概念代码。来自市场行业页的入口通过显式映射查找产业链，一对多时选择范围，无映射时提示尚未收录。
- 搜索不自动创建产业链、不实时触发全网采集。无结果、加载失败和未收录分别提示。
- 顶部固定显示分析范围、股票范围、产业资料截至日与版本；财务字段各自显示报告期，股票行情显示独立日期和时间。

### 3.2 行业速读与图谱

- 速读包含行业定义、主要产品、需求来源、核心环节、关注变量及当前资料缺口。
- 图谱主链按原材料、材料/零部件、制造、终端应用组织；设备、软件、服务、回收等按实际关系作为分支。不能用固定模板强行套用所有行业。
- 节点显示名称、简短作用、本站可浏览股票数、节点龙头数量和关键经营变量。统计绑定相同内容版本及股票池规则。
- 每条连线记录起点、终点和类型。供给箭头表示产品/服务流向；需求反馈箭头表示需求变化的传导方向；技术替代记录被替代对象和成立条件。
- 产品供给关系不能自动解释为两个具体公司存在客户/供应商合同。具体交易关系另需公司披露证据。
- 简明图使用明确的关键节点和主链标记；完整图包含全部已发布节点及关系。切换视图保持选中节点，隐藏节点给出返回完整图的入口。
- 点击节点打开详情；点击连线查看关系、解释和证据。无股票节点仍保留，区分“暂无已确认 A 股公司”和“公司资料待补充”。
- 颜色辅助区分关系类型，文本与线型同步表达；不得仅用颜色传达影响方向，不设置暗示涨跌预测的节点配色。
- 支持循环和多分支结构；按实际关系绘图，不将非树形产业网络强制转换成单一路径。

### 3.3 节点详情与影响分析

节点详情包含“作用与产品、上下游关系、竞争格局、影响分析、相关公司、资料来源”。

每条影响分析固定包含：变化因素、作用对象、成本/售价/销量/库存/资本开支等传导路径、有利/不利/混合/不确定方向、成立条件、时间特征、验证指标、证据、事实或分析判断标记。

- 首版展示资料支持的条件性分析，不提供自动收益预测和无法校验的影响百分比。
- 供给收缩、需求增长、扩产、价格变化、政策变化和技术替代分别解释，不压缩为统一“利好/利空”结论。
- 同一变化允许对不同企业产生不同影响，说明库存、合同、议价能力、自供比例等条件；经营影响不直接替换成股价结论。
- “短期/中期/长期”必须说明对应的经营过程；无法确认传导时间时标记未知，不虚构精确天数。
- 事实引用和分析推断分别标记。推断仍需列出支持材料与推理条件；结论有分歧时并列说明，缺少证据时登记待核验。
- 行情表现可以用于观察，不据此确认因果关系；既有资金流向不作为产业链影响强度或节点龙头证据。

### 3.4 公司映射、财务与龙头

| 信息 | 必须执行的规则 |
| --- | --- |
| 证券匹配 | 代码、交易所及已验证代码别名关联本地股票 ID，不按简称猜测 |
| 具体业务 | 每个公司—节点映射记录产品/服务和业务证据；同行业或同概念只能作为候选线索 |
| 参与方式 | 直接经营、控股子公司、参股、其他已披露方式分别展示；写明实际经营主体 |
| 经营阶段 | 已形成收入、试产、建设、研发、其他/未知分别保存；未来布局不标成当前成熟业务 |
| 财务金额 | 保留报告期、币种、合并/分部口径、原始值和单位；前端统一明确单位，不混币种排名 |
| 收入占比 | 仅用相同报告期、相同主体及可核对口径的分子/分母计算；合并分部、抵销或口径不明时保持未知 |
| 数值缺失 | null 与零分开；资料未披露、未收录、口径不可比的原因分别展示 |
| 多节点企业 | 可映射多个节点；全链列表按公司去重并列出其全部已确认节点，节点财务不直接相加 |
| 名单范围 | 展示已确认收录数量与可浏览数量；不能将其称为该节点全部企业数量 |

节点龙头分类为规模龙头、份额龙头、技术领先企业。每条认定保存产品边界、地域、期间、评价指标、值或定性依据、来源和审核日期。

- 只有证据支持时才显示龙头标签，不以公司市值、指数权重或最近涨幅替代。
- 技术领先可以是证据支持的定性判断，不自动转换为名次；来源只支持“领先企业”时不能扩大为“全球第一”。
- 不强制选出前三，不因其他公司被股票池过滤而递补龙头。未纳入 A 股浏览范围的行业领先主体可以在节点说明中引用。
- 缺少同口径可比数据时展示代表企业并说明依据；代表企业不参与龙头数量统计。
- 首页、节点和比较页明确使用“节点龙头”；现有市场页保持“龙头股（行业指数权重前三）”口径。全局页脚随页面调整说明，避免将节点龙头解释为 SW2021 权重筛选。

### 3.5 股票列表、比较与收藏

- 默认显示当前节点“已确认开展经营业务”的公司；通过筛选查看全部参与方式和经营阶段。过滤后的统计需明确当前范围。
- 当前节点/全链、证券关键词、参与方式、经营阶段、龙头类型、排序与页码保存 URL。默认每页 20 条，可选 50/100 条。
- 全链先按股票 ID 去重，服务端对完整结果集排序后分页；默认按代码和交易所，金额与涨跌幅支持既有数值排序，空值末尾、同值顺序稳定。
- 全链列表不提供含糊的单一“节点收入占比”排序；多节点占比分别显示。当前节点财务比较也只对口径可比的数据排序。
- 从列表选择同节点 2～4 家公司进入 `/industry-chains/:id/compare`，比较参与业务、阶段、相关收入/占比、节点龙头依据及已有行情；财务与行情分区显示日期。
- 比较财务默认使用各选中公司共同存在的最近可比报告期；没有共同报告期时显示各自期间与“不可直接比较”，不排名、不填值。
- 比较集合使用 URL 保存股票 ID 和节点标识；服务端校验股票属于已发布节点且符合浏览规则，失效股票单独说明。
- 进入股票详情通过 `from` 携带经白名单校验的分析或比较页路径；返回恢复筛选、版本、选中节点与视图，滚动和图谱缩放使用会话状态恢复。
- 产业链来源的个股首版不请求市场顺序接口，隐藏上一只/下一只；市场与热门板块原有分支回归。
- 链和节点收藏使用稳定 ID、本地独立存储键及版本号；股票沿用现有自选。收藏回查当前版本，已移除节点显示不可用并允许移除，不能静默跳到同名节点。
- 收藏支持多标签同步、去重和存储失败提示；不新增账户体系。

## 4. 数据模型与版本契约

具体字段在 M0 冻结，下表是必须表达的实体和约束。首版仍采用 SQLAlchemy 与 SQLite，不为图谱额外引入图数据库。

| 拟定实体 | 职责与关键字段 |
| --- | --- |
| `IndustryChain` | 稳定身份、规范名称、当前已发布 revision 指针 |
| `ChainRevision` | 范围、别名、行业显式映射、速读、资料截至日、状态、审核人与时间、内容 hash、发布与变更说明 |
| `ChainNode` | revision、稳定 node_key、名称、环节类型、作用、关键变量、主链/分支标记、布局顺序 |
| `ChainEdge` | revision、稳定 edge_key、同版本起终节点、关系类型、方向、说明 |
| `ChainAnalysis` | 同版本链/节点/连线关联、变化因素、作用对象、方向、机制、条件、时间特征、观察指标、事实/推断分类 |
| `ChainStockLink` | 同版本节点与 Stock、经营主体、具体产品、参与方式、经营阶段；保留未匹配源证券信息供维护 |
| `ChainBusinessMetric` | 公司节点关联、报告期、披露日、主体与统计口径、金额/占比、币种、单位、分母来源、计算方法 |
| `ChainLeaderClaim` | 公司节点关联、龙头类型、产品、地域、期间、指标与依据、认定状态 |
| `ChainSource` | 来源 URL、标题、发布日、报告期、取得日、内容 hash、必要的本地摘录或受控文件标识、可访问状态 |
| `ChainEvidence` | 对应主张/实体、source、页码/章节/段落定位、摘要、支持或反驳关系；在导入校验中保证引用目标存在 |
| `ChainImportRun` | 任务、输入 hash、开始/结束、状态、错误、校验与审核结果、关联 revision |

实施约束：

- 节点、连线、映射、分析和指标均隶属一个内容版本；复合约束及校验阻止连线端点跨版本、关联节点跨链。
- 每个版本同一 `node_key`/`edge_key` 唯一；股票映射允许多产品和多经营主体，但同一证据支持的重复记录幂等去重。
- 正式发布版本不可原地覆盖，纠错生成新版本；来源内容变化生成新来源记录，不改写历史证据。
- 历史版本仅用于复核、收藏失效解释和版本一致性。首版股票筛选与报价仍按当前浏览规则执行，不声称提供历史股票池或历史投资回放。
- 数据库迁移前做 SQLite 一致性备份；迁移不删除行情、历史、行业、概念、资金或现有收藏。验证数据库与日常数据库分开。

## 5. 资料采集、审核与发布

### 5.1 数据能力矩阵

| 内容 | 候选来源与路径 | M0 必须核实 |
| --- | --- | --- |
| 行业身份/候选公司 | 现有行业、概念与股票库 | 只作为发现线索，不能直接生成公司节点归属 |
| 公司实际业务 | 年报、招股书、公司公告；巨潮等公开披露平台；可人工登记来源 | 经营主体、产品、报告期、页码定位、URL 可访问性 |
| 主营收入/成本 | 披露文件优先；Tushare `fina_mainbz` 可选 | 权限、单位、币种、分部与合并口径、缺失、重复及与报告对照 |
| 竞争格局 | 行业协会、官方统计、明确口径的公开研究 | 产品范围、地域、期间、可比性、原始依据 |
| 价格/产量/订单等指标 | 官方统计、行业公开资料、公司披露 | 是否实际可获得；首版至少列观察指标，无真实序列不绘图 |
| 行情与证券状态 | 现有本地 API 和共享浏览股票池 | 日期、时间、来源、旧数据状态与统一过滤 |

来源参考：[Tushare 申万行业成分](https://tushare.pro/document/2?doc_id=335)、[Tushare 主营业务构成](https://tushare.pro/document/2?doc_id=81)、[巨潮资讯](https://www.cninfo.com.cn/new/index)。这些是候选能力和资料入口，不代表本项目已完成权限、连接、完整性及部署验证。

免费行情要求保持现有规则。新增产业链资料首版采用公开资料和人工维护，不默认购买研究数据或模型服务；可选 Tushare 或 AI 通道单独登记可用性和费用边界，缺少权限时不阻断已发布产业链浏览。

### 5.2 内容流程

专题事实维护流程：登记来源 → 编写结构化内容 → 自动校验 → 人工审阅证据与判断 → 标记 reviewed → 事务发布。全行业数据商/规则分析流程：定时采集 → 完整性与变更检测 → 重建 → 全行业自动结构校验 → 事务发布，保留各项未核验标注。

- 首版使用版本化 JSON 内容包和维护 CLI，不新增管理后台。内容包可置于 `config/industry_chains/`，schema 与说明一同维护；大报告文件不直接纳入 Git。
- 自动校验覆盖身份与引用、证券匹配、日期、金额/占比、方向、重复、证据定位、必填条件和图谱结构。
- 人工审核负责判断材料是否真正支持业务、关系和龙头主张；机器校验通过不自动变成内容审核通过。
- 已发布的公司映射、连线和龙头主张必须有证据引用；分析判断必须有支持材料、推理条件和分类标签。无资料节点可以保留，不能带无依据的确定性结论。
- 同版本的材料可以来自不同报告期，但必须明确各自期间与整体资料截至日。出版日期、取得日期、审核日期、报告期与行情时间分别保存。
- 状态为 `draft → validated → reviewed → published`；校验失败进入 `failed` 并保留错误。CLI 发布仅接受 reviewed 内容，记录维护人，不以已有公开 GET 接口提供未保护的发布能力。
- 新版本写入与当前 revision 指针切换在同一短事务内完成；网络请求及材料解析在事务外执行。
- 内容 hash 相同的重复导入不生成重复版本；并发维护使用产业链任务锁，不能长时间占用行情任务的锁或 SQLite 写锁。
- 来源失效、业务调整、新报告或相互矛盾材料进入待复核清单。相关主张可显示“待复核”，不因链接暂时打不开便断言事实失效；无法支持的结论经复核后在新版本撤销。
- 外部失败保留旧版本和原日期；更新任务失败不阻断网站启动、行情和热门板块。

拟新增 CLI 子命令：`validate-chain`、`import-chain`、`review-chain`、`publish-chain`、`doctor-chain`。具体参数在 M0 冻结；发布前必须提供可查看的校验和审核结果。计划编制阶段未执行迁移；本次实现已执行 0011 迁移和三条样板的本地发布。

## 6. API 与一致性约定

首版公开 API 为只读，写入维护通过本地 CLI。接口统一置于 `/api/industry-chains`。

| 接口 | 参数与职责 |
| --- | --- |
| `GET /api/industry-chains` | `q`、`industry_id`、分页；搜索已发布名称/别名，返回候选范围和匹配原因 |
| `GET /api/industry-chains/{id}` | 可选 `revision`；行业范围、速读、资料状态、统计和变更摘要 |
| `GET /api/industry-chains/{id}/graph` | `revision`、简明/完整视图；返回节点、连线、类型及统计 |
| `GET /api/industry-chains/{id}/nodes/{node_key}` | `revision`；节点说明、关系、影响分析与证据索引 |
| `GET /api/industry-chains/{id}/edges/{edge_key}` | `revision`；关系方向、传导解释、条件和证据 |
| `GET /api/industry-chains/{id}/stocks` | `revision`、`node_key`、关键词、参与方式、阶段、龙头类型、排序及分页；当前节点/全链公司 |
| `GET /api/industry-chains/{id}/compare` | `revision`、`node_key`、2～4 个 `stock_ids`、可选报告期；校验关系并返回可比性及缺失原因 |
| `GET /api/industry-chains/{id}/sources` | `revision`；资料清单、被引用位置及访问状态；内容按必要范围展示 |

公共元数据至少包含 `chain_id`、`revision_id`、`published_at`、`content_as_of`、`reviewed_at`、`review_status`、`pending_review_count`。引用资料的发布日与取得日随资料返回；财务报告期逐字段或逐业务记录返回；行情元数据使用现有报价结构。

- 首次详情返回具体 `revision_id`，后续图谱、节点、列表和比较请求固定该版本，防止更新中混合新旧结构。
- 默认 URL 不固定 revision，页面自动跟随最新分析并保持仍存在的节点、筛选、分页和滚动；显式 revision 固定历史版本，可主动恢复跟随。失效节点返回当前可用节点。比较页面固定选择时版本。
- 已发布旧版本可用于本次阅读一致性；draft/validated/reviewed 内容不从公开接口返回。已发布旧版本仍使用当前股票池，返回统计明确这一点。
- 不存在链、未发布版本或不存在节点为 404；不合法参数、跨链节点、重复/过多比较股票为 422；已过滤或不再属于节点的比较对象结构化返回原因并停止其数值比较。
- 搜索无匹配返回空集合；未收录不伪装成网络异常。资料缺失用 null 和原因，已有内容可读但待复核通过状态表达。
- 股票计数区分已登记、未匹配、被过滤、可浏览、当前筛选后数量；全链可浏览数量按公司去重。图谱统计、详情和列表遵守相同逻辑。
- 首版只读取本地内容，不在公开 GET 请求中调用报告抓取或模型。页面切换请求取消或忽略迟到结果。
- 资料链接限定有效 HTTP(S)；本地资料文件使用受控标识与根目录校验，不返回任意服务器路径，不执行来源中的脚本或指令。

- M6：复用既有验证库/样本，安全补充并说明保留方式；执行分层验收；更新既有需求范围及相应说明；维护本文状态表而非追加历史章节。

## 9. 后续阶段与实现边界

后续功能是本产品规划的一部分，单独验收，不影响已审核首版内容的正常浏览。下面的工作量是粗估，完成首版后根据真实依赖重估。

### M7：AI 辅助整理与未覆盖行业草稿

初估 5～8 个有效工作日，不包含新增资料采购和服务权限等待。

- 先核实模型服务、凭证、费用、可获取资料和运行环境；凭证只在后端读取，不能进入前端、日志或内容包。
- 基于取得的资料提取候选节点、关系、业务映射、指标与摘要，输出首版内容 schema；记录模型、提示模板版本、输入来源 ID、任务与 token/费用使用。
- 用户输入未覆盖行业时先确认范围，再创建异步草稿任务，明确“待核验”；任务创建不得发布正式版本。
- 将模型输出当作未信任候选内容，强制 schema 校验、证券身份匹配、证据存在及数值对照。引用存在不等于引用支持结论，仍需要人工审阅。
- 不允许生成无法定位的报告、链接、收入占比、市场份额和具体供应商/客户关系；无法取得资料时输出缺口，不能依赖模型记忆补成事实。
- 草稿、审核和正式版本分区；公开搜索与图谱默认只读已发布库。草稿访问应限制为授权维护入口，开放给远程用户前落实访问隔离与任务额度。
- 任务有界超时、取消、并发去重、限流和失败退避；页面只轮询本地任务状态。停用模型服务后首版已发布内容仍能浏览。
- 验收增加虚假引用、张冠李戴、冲突材料、来源中的指令、跨用户草稿、重复收费/提交等场景；模型结果不得绕过审核发布状态机。

### M8：情景推演

初估 3～5 个有效工作日。

- 输入原料涨价、终端需求下降、某环节扩产或技术替代等受控情景，选择作用节点、方向和必要条件。
- 沿已审核关系展示可能路径，区分一阶/间接影响与未知环节；保留每一步的成立条件和证据。
- 处理回路、最大遍历深度、多路径相反影响及路径去重，防止无限递归和单一正负号误导。
- 默认定性展示；没有验证过的弹性、成本占比和传导参数时不输出利润或股价变化百分比。
- 情景结果不修改正式关系和龙头标签；结果注明情景假设、内容版本与生成时间。

### M9：事件跟踪、跨链探索与持续更新

先做事件与来源验证，再单独估算。

- 将新报告、业务变更、政策和行业指标变化关联到节点，记录实际发生日、披露日和来源；观察结果与因果解释分开。
- 通过明确的跨链节点映射探索共享材料、设备和应用，不按同名直接合并。
- 建立待复核清单与版本差异，支持审核后更新节点、公司、指标与结论；报告期变化不能只改顶部日期。
- 更新提醒需另行定义触发条件、频率与通知渠道；未授权时不创建外部通知或自动发布任务。
- 可扩展产业链来源的股票顺序导航，但必须实现该来源的全量排序及跨页邻居契约，不能复用市场查询冒充产业链顺序。

### 12.1 来源与数值规则

- 官方行业分类 PDF 用于经营活动边界，框架的节点/关系由产品分析整理。关系不是已证实的企业供销合同，均标“分析判断”。
- 原公司文本不足以确认经营主体及阶段时，参与方式保留“待核实”、阶段保留“未知”；不能从经营范围推导项目已投产。业务词匹配也不能确认参与某个具体客户的供应链。
- 数据商分部数据保存真实报告期/分部名称/收入/分母/比例，披露日未取得保留 null；分母或源比例不一致则不展示占比。地区或行业口径不伪装成产品节点收入。数据商指标显示“汇总待核验”，禁止自动比较排名。
- `ChainSource` 表的 hash 仍是元信息 hash；内容源的 `snapshot_hash` 对公司资料指业务/财务快照内容，对原始公告指 PDF 文件 SHA256。取得时快照可在只读 API 回查。
- 688759.SH（必贝特）的目标期分部源为空；688808.SH（联讯仪器）源仅返回其他报告期。不称为公司“未披露”，不拿旧期数字填补 2025-FY/2026-H1。
- 原始资料补证采用 `config/industry_models/verified_facts.json`；该文件只合入公司事实，不再为某个行业覆盖业务分析逻辑。所有行业按 `business_logic.tsv` 和 `sector_analysis.tsv` 统一构建。更新核验结论需明确来源和时期。

### 12.2 后续仍须完成的研究核验

1. 对业务词候选逐公司核对原始公告、经营主体、节点产品与实际经营阶段；按影响程度优先处理 2,241 家待定位记录。
2. 取得各节点可靠市场份额、销量/规模或技术证据，分别按产品/地域/时期核验，不强制每个节点出龙头。
3. 对分部收入补齐原始披露日、合并主体、币种和统计边界；同报告期并不自动等于同口径。
4. 对 165 个分析框架逐项补充专项政策/技术/供需资料和条件性影响依据；各行业规则已独立补齐，但行业活动定义不能替代交易合同或专项实证。
